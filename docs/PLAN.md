# 企画・設計書（ブラッシュアップ版）

- 元の要望：「文化祭のステージで使う用に、取得した音声から映像をいい感じに変化させるものをつくりたい。リアルタイムで反映させるために可能な限り遅延が無いようにして欲しい」
- この文書は、企画担当のエージェントがブラッシュアップした設計に、実装中に分かったことと変更点を加えたものです。

## 0. 前提

- **使う場面**
  - ステージ脇のノート PC（Windows か Mac か未定）をプロジェクターにつなぎます。
  - 音は PA 卓のライン出力を USB オーディオ IF 経由で、または内蔵マイクで拾います。
- **会場の条件**
  - インターネットは使えない前提です（完全オフラインで動く必要があります）。
- **操作者**
  - 技術に詳しくない友人かもしれません。キー数個で破綻しないことが必須です。

## 1. 体験設計：「音と映像が合ってる」と感じさせるもの（効く順）

1. **立ち上がりを合わせる**
   - 光り始めと鳴り始めが合っているかで、人は同期を判断します。
   - 値は「立ち上がりは即時、減衰だけ平滑化」で作ります。
   - 立ち上がりを滑らかにするのは最大の失敗です。
2. **1 ヒット = 1 イベント**
   - 音量を明るさに直結させるのではなく、ヒットごとにリングが生まれる・構図が変わる、という「数えられる」対応にします。
3. **楽器ごとに担当する見た目を分ける**

| 音 | 担当する見た目 |
|---|---|
| キック | 大きさ・中心からの波 |
| スネア（ギターのストロークも含む） | 切替・色 |
| ハイハット | きらめき |
| 低域の持続音 | うねり |
| 全体の音量 | 速度 |
| 数秒単位の盛り上がり | 密度・彩度 |
| ブレイク明けの強打 | インパクト |

4. **曲の大きな起伏を見せる**：A メロとサビの差を、要素の密度や彩度の差として出します。
5. **反応させすぎない**：1 シーンで主役になる対応付けは 2〜3 個に絞ります。
6. **会場に合わせる**
   - 明るい体育館と、光量の弱い 4:3 のプロジェクタを想定します。
   - 黒地に高彩度の色を置き、線を太くし、重要な要素は中央に寄せます。
7. **バンド名・曲名を出す**：タイトル表示と曲名の重ね表示は必須（MVP）に含めます。

## 2. 技術選定（決定事項）

- **形態**
  - 静的 HTML で、Chrome / Edge 専用です。file:// で動き、サーバも不要です。
  - 開発は classic script でファイルを分け、`tools/build.mjs` で単一ファイル `dist/momosai-vj.html` にします。
- **音声**
  - 取得: `getUserMedia({echoCancellation:false, noiseSuppression:false, autoGainControl:false, channelCount:{ideal:2}, latency:{ideal:0}})`
  - `AudioContext({latencyHint:'interactive'})`。sampleRate は指定しません。
  - `AnalyserNode(fftSize 8192, smoothing 0)` を rAF の先頭で同期的に読み出し、新規サンプルだけを DSP に渡します。
- **使わないもの**
  - AudioWorklet（file:// で読み込めないことを実測で確認）
  - SharedArrayBuffer（COOP/COEP ヘッダが必要）
  - ScriptProcessorNode
  - ローカルサーバ、Electron
- **描画**
  - WebGL2 の全画面フラグメントシェーダで描き、オフスクリーンバッファ（倍率は自動調整）と仕上げパスの 2 段にします。
  - コンテキスト属性は `alpha:false`, `antialias:false`, `preserveDrawingBuffer:false`, `desynchronized:true` です。
- **依存**
  - ランタイムの依存はゼロです。開発用は `playwright@1.56.1`（バージョン固定）のみです。

## 3. 遅延バジェット

| 段階 | 典型値 | 対策 |
|---|---|---|
| AD 変換 + ドライバ | 3〜15ms | USB IF を使う。Windows の「オーディオの機能拡張」を OFF |
| ブラウザの取り込み | 10〜20ms | 音声処理をすべて OFF |
| 音声処理グラフ | 3〜12ms | `latencyHint:'interactive'` |
| **解析窓** | FFT2048 なら 20〜40ms | **IIR + 128 サンプル刻みで 3〜8ms** |
| **平滑化** | Analyser の既定値なら約 100ms 級 | **0（立ち上がり即時）** |
| rAF 待ち | 0〜16.7ms | ― |
| 描画→表示 | 17〜33ms | GPU 負荷をフレーム時間の 50% 以下に、`desynchronized` |
| プロジェクタ | 20〜100ms | ゲームモード、台形補正 OFF |

- 目標は「システム全体で 80ms 以下、ソフト部分で 1 フレーム + 5ms 以下」です。
- 客席では音が距離に応じて遅れて届く（10m で約 29ms）ので、体感の遅れはさらに小さくなります。

## 4. 解析（実装したもの）

- **帯域**：4 次バターワースで 5 帯域に分けます。

| 帯域 | 範囲 | 用途 |
|---|---|---|
| b0 | 35–150Hz | キック |
| b1 | 150–400Hz | ベース・胴鳴り |
| b2 | 400Hz–2kHz | 中域 |
| b3 | 2–5kHz | スネア |
| b4 | 6kHz 以上 | ハイハット |

- **低域（b0, b1）は直交エネルギー y² + (y'/ωc)² で測ります。**
  - 41Hz のベース（周期 24ms）でも、2.7ms ごとのエネルギーが位相で脈打ちません。
  - これでバンド演奏時のキック再現率が 0.47 から 0.88 に改善しました。
- **オンセット（立ち上がり）検出**
  - flux = max(0, 直近 W ホップの dB − L〜L+R ホップ前の最大値)
  - しきい値 = μ + K·σ + 最小上昇量
  - μ と σ は**しきい値で切り詰めてから更新**します（ウィンソライズ）。大きなヒット自体で σ が膨らみ、2 打目以降を取りこぼすのを防ぎます。
  - **相対ゲート**：帯域の最近のピーク（4dB/秒で下がる）より relDb 以上小さい立ち上がりは無視します。ハイハットの漏れによるスネア誤検出と、ベースの発音によるキック誤検出を防ぎます。
  - **キックとスネアの区別**：スネア検出から 5 ホップ以内で、キック帯域のピークより 7dB 以上小さいキック候補は捨てます（スネアの胴鳴りの漏れ）。
  - 全体が無音（ゲート外）の間はオンセットを出しません（定常ノイズのゆらぎで反応しないように）。
- **アクセント（キメ）**：3 帯域以上が同時に立ち上がり、かつ全帯域の短時間音量が「少し前までのピーク + 3dB」を超えたときに出します。単調なループでは稀にしか出ず、セクションの頭では出ます。
- **インパクト**：ブレイク（速い音量 < 遅い音量の 15% が 250ms 以上続く）のあと 4 秒以内に強打が来たら出します。
- **自動正規化**：dB 上の 24dB 幅で、上昇 τ0.3s、下降 τ8s です。無音中は凍結します。過去だけを見るので遅延はゼロです。
- **見た目用の値**
  - FFT2048（ハン窓）はスペクトル 64 本（+3dB/oct 補正）と重心の算出にだけ使います。
  - 波形は立ち上がりのゼロ交差でトリガし、4 サンプル平均で約 43ms 分を表示します。

## 5. シーン

| キー | シーン | 主な反応 |
|---|---|---|
| 1 | 波紋 | キック＝中心からリング、スネア＝ランダムな位置から二重リング、ハイハット＝格子の点 |
| 2 | トンネル | 音量＝前進、キック＝手前へ来る光の波、スネア＝ねじれ、アクセント＝回転方向の反転 |
| 3 | 地平線 | 音量＝床のスクロール、キック＝床を走る光の帯、スペクトル＝山脈、スネア＝グリッドの色 |
| 4 | オーロラ | 低域（ゆっくり追従）＝うねり、中域＝流れの速さ、キック＝中心の小さな脈動 |
| 5 | 万華鏡 | 前フレームの再利用、キック＝多角形とズーム、スネア＝分割数、アクセント＝残像リセット |
| 6 | グリッチ | キック・スネア＝カット切替（0.3 秒に 1 回まで）、高域＝RGB ずれ、アクセント＝反転 |
| 0 | タイトル | バンド名 / 終演の文字、キック＝わずかに拡大、音量＝にじみ |

**仕上げパス**では次を合成します。

- フラッシュ（制限器を通る）
- 暗転
- 全体の明るさ
- インパクト（色収差 + ズーム）
- 曲名の重ね表示
- 周辺減光
- ディザ
- 遅延計測用の四角

## 6. 光過敏対策（必須）

- 全画面の明るさが大きく変わる演出（フラッシュ・反転・残像リセット・ストロボ）は、すべて `FlashLimiter` を通します。
  - 1 秒に 3 回まで、最短 200ms 間隔です。
  - 同じフレームの演出は 1 回として数えます。
- 鮮やかな赤のフラッシュは白に置き換えます。
- シーン側では、ビートごとに画面全体の明るさを大きく変えません。
  - 実装中、オーロラが音量に直結していて 1 秒に最大 13 回の明滅になっていたため、ゆっくり追従する値に変えて 1 回以下にしました。
- **自動テストで確認しています。** 全シーン × 自動フラッシュ ON × 140BPM で、画面を 4×3 の領域に分け、各領域の相対輝度の逆向きの変化（10% 以上）を数えます。どの 1 秒でも 3 フラッシュ以下であることを確かめます。

## 7. 操作

- **キー**
  - `event.code` で判定するので、日本語入力が ON でも効きます。
  - 入力欄にフォーカスがある間は無効です。
  - 一覧は手順書を参照してください。
- **シーン切替**は次のビート（キック/スネア/アクセント、強さ 0.5 以上）で実行し、最大 1 秒待ちます。`Shift` で即時です。
- **セットリスト**：1 行 1 曲で `曲名 | シーン | パレット | notitle` と書きます。`@band`・`@end` も使えます。
- **オート**
  - 24 秒以上たったあとのアクセントで次のシーンへ切り替えます。アクセントが来なければ 34 秒以上たったあとの強いキックで切り替えます。
  - 曲にシーン指定があれば、その中で順番に切り替えます。
  - 指定がなければ、盛り上がりの 3 段階に合わせて選びます。
  - 無音が 8 秒続くとタイトルにし、強打で元に戻ります。
  - **タイトル表示中は自動で離れません**（開演前・MC・終演で勝手に切り替わらないように）。
- **事故防止**
  - スリープ防止（Wake Lock）
  - Esc のキー取り込み（長押しでのみ全画面解除）
  - 離脱確認
  - 2 秒でカーソル非表示
  - デバイスの自動再接続
  - AudioContext の見張り（停止したら resume、時間が進まなければ作り直し）
  - WebGL コンテキストの復旧
  - 壊れたシェーダの除外
  - フレーム単位の例外隔離（同じシーンで 3 回続いたらタイトルへ）

## 8. テスト

- **単体テスト（Node）**
  - フィルタ特性、FFT、検出精度と遅延
    - クリックトラック：全数検出、平均 8ms 以下、最大 12ms 以下
    - 8 ビート：各 0.9 以上
    - バンド演奏：キック再現率 0.85 以上、誤検出率 10% 以下
  - ノイズで反応しないこと、レベルの段差、インパクト、アクセントの頻度
  - チャンクの切り方に依存しないこと、resync
  - セットリスト、フラッシュ制限、コントローラ、オート、MIDI
- **E2E（Playwright、配布物を file:// で開き、偽マイクを使う）**
  - 起動、マイクの流れ（音声処理 OFF、位置合わせ）、キー操作とロック
  - ショー開始、ブラウザ内の遅延（中央値 40ms 以下）
  - 再接続、見張り、45 秒の連続運転（ヒープ増加 5MB 未満）、許可の拒否
  - 全シーンの描画、反応、暗転、フラッシュ制限、光過敏（全シーン・オート）
  - コンテキストの喪失、シェーダの失敗
- **実機の総合遅延**：スマホの 240fps 撮影と遅延計測用の四角で確認します（手順書 10 章）。

## 10. 拡張（2 回目の依頼：いろいろな場所・音楽で使えるように）

依頼は「もっといろいろなところや音楽で使えるように」「便利な機能を色々追加」でした。対応内容は次のとおりです。

### いろいろな音楽

- **音楽のタイプ（プロファイル）**
  - 対応は「おまかせ / EDM・ダンス / ヒップホップ / アコースティック / しっとり」の 5 種類です。
  - それぞれ、解析パラメータ・反応の速さ・オートの切替間隔・使うシーン・自動フラッシュの有無を切り替えます（`src/core/profiles.js`）。
- **ドラムの無い曲**
  - 中域（150Hz〜5kHz）に、発音の立ち上がりを拾う検出器を追加しました。
  - 「ドラムらしいキック」が 6 秒間に 1 回以下になると、自動でメロディモードに切り替わり、発音をキックとして扱います。
  - ドラムらしいかどうかは、キック時の「低域÷中域」のエネルギー比が -2dB を超えるかで判断します。ピアノの低音のキック帯域への漏れはこの比が -6dB 以下なので、ドラムとは区別できます。
- **テンポ推定（`src/dsp/tempo.js`）**
  - 帯域ごとの立ち上がりの強さを約 10ms ごとに 8 秒分ため、自己相関で周期を求めます。
  - 120BPM 付近を優先し、90〜180BPM に収まるよう倍・半分を補正します。
  - 拍の位置は、櫛形の和が最大になるところとします。
  - 4 拍のうちキックが最も強い位置を小節の頭とします。入れ替えはヒステリシス付きです。
  - タップテンポ（Enter）は 2 分間、自動推定より優先します。
  - 用途はオートの小節頭での切替、拍の脈動（`u_beat`）、表示です。先回りして光らせることはしません。
- **新しいシーン**：イコライザー・星空・オシロ（静かな曲・電子音楽向け）と、テストパターンを追加しました。

### いろいろな場所

- **表示の調整**：回転（縦置き画面・逆さ吊り）、左右・上下反転（スクリーンの裏から投影）、サイズ・位置に対応しました。シーンは回転後の縦横比で描画します。
- **出力ウィンドウ（2 画面）**
  - 出力側が音声・解析・描画を担当するので、遅延は 1 画面のときと同じです。
  - 操作側は `app.show` と `app.engine` をリモコンに差し替え、操作を postMessage で送ります。状態は 1 秒に 10 回返ってきます。
- **PC で再生中の音**：画面共有の音声（`getDisplayMedia`）で、YouTube や DJ ソフトの音に反応できます。
- **音声ファイル**：複数選ぶと連続再生します。次の曲は再生中に先にデコードしておきます。
- **展示用**：起動したら前回の入力で自動的に開始できます。

### 便利な機能

- ロゴ画像（タイトル / 隅に透かし）
- テロップ 3 枠（Q / W / E）
- 開演カウントダウン
- 前回の続きから再開
- オートで使うシーンの選択
- 動きの大きさ
- フラッシュを一切使わない設定
- 無音とみなす音量
- 30fps 上限
- MIDI の CC もメソッド経由に（2 画面のときも使えるように）

### 安全

- 新しいシーンも光過敏テストの対象にしました。
- オシロは当初 1 秒に 3.5 回の明滅になったため、次の 2 点で 1.5 回まで下げました。
  - 振れ幅はゆっくり追従させた音量にする
  - 新しい線は前フレームと半分ずつ混ぜる

## 11. 拡張（3 回目の依頼：声・司会・課題 D・映像の追加）

### 声

- **ピッチ（音程）**：`src/dsp/pitch.js`。2kHz の低域通過 → 約 12kHz に間引き → YIN（窓約 36ms）を約 10ms ごと。
  - YIN の「固定の閾値を下回る最初の谷」では、母音のフォルマントと重なった 3 倍音を拾うことがあったため、「最小の谷とほぼ同じ深さの谷のうち、いちばん短い周期」を選ぶ方式にしました。
- **音程の変わり目**（`src/dsp/voice.js`）：ゆっくり追従する中心から 0.9 半音以上ずれ、ずれた先の音程が 3 回そろって続いたとき。
  - ビブラート（±0.6 半音）では出ない、合唱の和音（周期性が低い）では出ない、を合成音で確かめています。
  - 歌のタイプでは、これもキックとして使います（音量の立ち上がりの直後 0.25 秒は重ねない）。
- **話し声の判定**：約 4 秒の窓で 5 つの手がかりを組み合わせます。実際の朗読 3 本・読み上げ 3 本と、器楽 6 曲・歌入り 1 曲・合成音源で調べて決めました。
  - 音量の谷の割合（1 秒ごとに平均の半分未満のフレーム）：話し声 0.3〜0.45 / 音楽 0.05〜0.2
  - 音程の平らさ（50ms の音程の幅が半音の半分未満の割合）：話し声 0.3〜0.45 / 音楽 0.65〜0.9
  - 音域の広さ・有声の割合・有声が続く長さ
  - 判定中は、自動フラッシュの元（キメ・ブレイク明けの一撃）・拍・テンポ推定・子音のスネア/ハイハット扱いを止めます。
  - 話の間の沈黙（4 秒まで）は状態を保ちます。
- **MC の誤フラッシュ対策**（判定前の 2〜3 秒にも効くもの）
  - 「ブレイク明けの一撃」はドラムらしいキック（低域が中域より強い）かキメだけにしました。
  - キメは低域か高域も一緒に立ち上がったときだけにしました（声の出だしは中域だけ）。
- **音楽のタイプ**に「歌」「司会・スピーチ・朗読」を追加しました。
- **設定**：「MC のあいだはタイトルにする」を追加しました。演奏が 2.5 秒続いたら元のシーンに戻ります。

### 映像（9 シーン追加 → 19 シーン）

- Shift+数字の段に、次の 9 シーンを置きました。
  - 声の輪・メロディ線・声紋：声を見せるもの
  - 花火・花びら・サークル：盛り上がる・華やかなもの
  - 光の粒・波・煙：静かなもの

## 13. 拡張（5 回目の依頼：BPM・フラッシュの上限・激しさ・パネルの折りたたみ）

## 14. 拡張（6 回目の依頼：シーンの動き・PC で再生中の音・激しさとパレットの自動）

| 要望 | 対応 |
|---|---|
| 星空・光の粒・花びらが止まって見える | 動きの量を「0.1 秒あたりの画面の変化」で測り、変更前後を同じ音で比べながら調整。星空は遠近つきのワープ（近づくほど速く、進む向きに伸びる光の筋）、光の粒は玉ごとのふらつきと層ごとの向き、花びらは落下・揺れ・回転を速く |
| 波・サークルの内側をもっと激しく | 波の高さは音にすばやく追従させ（形だけが変わるので光過敏の対象外）、色・明るさはゆっくりした音量で。キックへの反応は、ばね（持ち上がって戻る）で位置を動かす。サークルの内側の輪は、線までの距離を傾きで補正して、急な斜面でも線が途切れないように |
| 煙・オーロラに流体らしさ | 煙：流れ関数を大・中・小の 3 段にし、大きな渦で細かい渦の位置も流す。キックの位置に渦（速度場に回転を足す）。にじみを減らして筋を残す。オーロラ：座標を大きく波打たせてから多重に歪ませ、キックの波紋で座標を押す |
| メロディ線をきれいにつなぐ | シーンの `update` で音程の履歴を下ごしらえして、float のまま uniform（`vec4[32]`）で渡す。履歴が進むまでの端数（`u_sub`）で左へなめらかに流す |
| PC で再生中の音が取り込めない | 実機の Chrome で実物の共有の画面を自動操作（UI オートメーション）して切り分け：内蔵スピーカーが既定のとき、同じ Chrome が先に音の出力デバイスを開いていると、システム音声の取り込みが無音になる。`AudioContext` は動かすだけで出力デバイスを開くので、この入力では使わず、`MediaStreamTrackProcessor` でトラックから直接サンプルを読む（`AudioEngine._startTap`。`pull()` はたまった分をそのまま渡す）。出力先なしの `AudioContext`（`sinkId: none`）は時計が遅れるので不採用。共有の画面は `displaySurface: 'monitor'` で「画面全体」から開く（Windows） |
| 激しさ・パレットに自動 | `ShowController._autoIntensity`（盛り上がり → 0〜3 の段階を小数で追い、`INTENSITY` の行を補間）、`_autoPalette`（曲の区切りで盛り上がりに合った色へ。色は 1.5 秒かけて補間） |
