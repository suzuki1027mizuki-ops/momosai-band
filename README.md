# MOMOSAI VJ — 文化祭バンドステージ用 音声リアクティブ映像

バンドの音（PA 卓のライン出力やマイク）を拾い、**ほぼ遅延なし**でプロジェクターの映像を変化させるシステムです。

- **ブラウザだけで動きます。** Chrome / Edge で HTML ファイルを開くだけで、インストールもネット接続も要りません。
- **音から光まで、ソフト側の遅延はおよそ 1 フレーム以内です。** キックの検出は 128 サンプル（約 2.7ms）刻みで行います。
- **映像は 7 シーンあります。** 波紋・トンネル・地平線・オーロラ・万華鏡・グリッチ・タイトルで、すべて全画面シェーダです。
- **キック・スネア・ハイハット・キメ（アクセント）・ブレイク明けの一撃を検出し、それぞれ違う動きに割り当てています。**
- **セットリスト機能があります。** → キーで次の曲に進むと、曲名が表示され、曲ごとに決めたシーンと色に切り替わります。
- **オートモードがあります。** 操作者が何もしなくても、盛り上がりに合わせてシーンが自動で切り替わります。
- **光過敏対策をしています。** 全画面の強い明滅は 1 秒に 3 回までに制限し、自動テストで確認しています。

> 当日の操作手順は **[docs/MANUAL-ja.html](docs/MANUAL-ja.html)**（印刷用）にあります。
> 企画・設計の経緯は **[docs/PLAN.md](docs/PLAN.md)** にあります。

## すぐ使う（操作する人向け）

1. `dist/` フォルダをまるごと本番用のノート PC にコピーします。
   - `C:\momosai-vj\` のように、英数字だけの場所に置くのがおすすめです。
2. 起動用のファイルをダブルクリックします。
   - Windows: `start-windows.bat`
   - Mac: `start-mac.command`（初回は右クリック →「開く」）
   - うまくいかないときは、`momosai-vj.html` を Chrome のウィンドウにドラッグしても開けます。
3. 右側のパネルで入力を選び、**▶ 音声入力を開始** を押します。
   - マイクの許可を求められたら「許可」を押します。
   - メーターが動けば OK です。
4. **ショー開始（全画面）** を押します。
5. 本番中のキー操作は次のとおりです。

| キー | 動作 |
|---|---|
| `1`〜`6` | シーン切替（次のビートで切り替わる） |
| `0` | タイトル（バンド名） |
| `→` / `←` | 次の曲 / 前の曲（曲名を表示） |
| `Space` | フラッシュ |
| `B` | 暗転 |
| `A` | オート ON/OFF |
| `C` | 色を変える |
| `↑` / `↓` | 感度 |
| `H` | キー一覧 |
| `M` | 設定パネル |
| `L` | ロック（誤操作防止） |

音源なしで試したいときは、入力で **デモ音源** を選びます（約 75 秒のバンド演奏が流れます）。

## 遅延を小さくするための設計

| 段階 | やっていること |
|---|---|
| 入力 | `getUserMedia` のエコー除去・ノイズ抑制・自動ゲインをすべて OFF にし、WebRTC の音声処理を通しません。`AudioContext({latencyHint:'interactive'})` を使います。 |
| 受け渡し | `AnalyserNode`（平滑化 0）を描画フレームの先頭で同期的に読み出します。前回の末尾 32 サンプルと完全一致する位置を探し、新しく届いた分だけを取り出します。取りこぼしも二重処理もありません。AudioWorklet・SharedArrayBuffer は file:// で使えないうえに、データの新しさは同じなので使いません。 |
| 解析 | FFT は使わず、4 次バターワースの IIR フィルタバンク（5 帯域）を 128 サンプル刻みで回します。低域の 2 帯域は直交エネルギー（y² + (y'/ω)²）で測るので、ベースの波形で値が脈打ちません。 |
| 立ち上がり検出 | 帯域ごとに「dB の上昇量 > 平均 + K·σ + 最小上昇量」で判定します。統計は外れ値を切り詰めて更新し（ウィンソライズ）、帯域の最近のピークと比べて小さすぎる立ち上がりは無視します（相対ゲート）。不応期とヒステリシスで連続発火を防ぎます。 |
| 見た目 | 値は「立ち上がりは即時、減衰だけ平滑化」です。ヒットした瞬間のフレームで最大になります。 |
| 描画 | WebGL2 の全画面シェーダです。`desynchronized` と `alpha:false` を使い、描画解像度は自動調整します。シェーダは起動時に事前コンパイルして一度描いておきます。 |

測定値（このリポジトリのテストで確認したもの）は次のとおりです。

| 項目 | 結果 |
|---|---|
| キックの検出遅延（アルゴリズム） | 平均 7.9ms、最大 8.7ms（クリックトラック） |
| 音がグラフに入ってから画面のフレームに反映されるまで（ヘッドレス Chromium・60Hz） | 中央値 9〜16ms（rAF 待ち 0〜16.7ms を含む） |
| 検出精度：ドラムのみ（8 ビート） | キック・スネア・ハイハットの適合率・再現率がいずれも 0.94 以上 |
| 検出精度：ドラム＋ベース＋歪みギター | キックの再現率 0.88、誤検出率 8% |

実機での総合遅延（AD 変換・OS・プロジェクタを含む）は、手順書の「遅延の測り方」の方法で確認してください。プロジェクタの「ゲームモード」が一番効きます。

## 開発

```bash
npm install             # playwright（テスト用。ブラウザのダウンロードは不要な環境を想定）
npm run build           # dist/momosai-vj.html（単一ファイル）を生成
npm test                # build → テスト用音声生成 → 単体テスト → E2E
npm run test:unit       # DSP・演出の単体テスト（Node だけで動く）
npm run test:e2e        # Playwright（Chromium・偽マイク）で dist を file:// で開いて検証
```

- **開発中の表示確認:** `index.html` をそのまま Chrome で開けばそのまま動きます（ビルド不要）。
- **テスト用の URL パラメータ:**
  - `?test=1`: テスト API `VJ.testing` を有効にする
  - `&scale=1`: 描画倍率を固定する
  - `&forceShaderFail=glitch`: シェーダの失敗を再現する
- **ソースの形式:** classic script（ES Modules 不使用）です。file:// で動かすためと、Node のテストから `vm` で読み込むためです。

### ファイル構成

```
index.html              開発用の入口（script タグの順番が読み込み順の唯一の定義）
src/core/               名前空間・設定・保存
src/dsp/                IIR フィルタ・FFT・包絡線・オンセット検出・特徴量
src/audio/              AudioEngine（入力・位置合わせ・再接続）、デモ/テスト用シンセ
src/gfx/                WebGL2 補助・文字テクスチャ・レンダラー
src/scenes/             シーン（GLSL）と仕上げパス
src/show/               パレット・セットリスト・フラッシュ制限・オート・ShowController
src/ui/                 キー操作・HUD・事故防止・MIDI・設定パネル
src/main.js             起動とフレームループ
tools/build.mjs         単一 HTML への結合
launcher/               起動スクリプト（build で dist/ にコピー）
docs/                   手順書・企画書
test/unit, test/e2e     テスト（helpers/ に読み込み・ブラウザ起動・光過敏判定）
dist/                   配布物（コミット済み。操作者はビルド不要）
```

### シーンの追加

`src/scenes/xxx.js` で `VJ.scenes.register({ id, key, nameJa, frag, update })` を呼び、`index.html` に script タグを足します。

- 共通の uniform（`u_kick`, `u_kickEv[8]`, `u_level`, `u_pal[4]` など）は `src/scenes/common.js` を参照してください。
- **ビートに合わせて画面全体の明るさを大きく変えないでください。** 動き・大きさ・色相で反応させます。
- 光過敏テスト（`test/e2e/render.test.mjs`）が通ることを確認してください。

## 確認済みの技術事項

ヘッドレス Chromium 141 で確認しました。

- file:// でも安全なコンテキストとして扱われ、`getUserMedia`・`localStorage`・URL のクエリが使えます。
- file:// では `AudioWorklet.addModule` が Blob URL でも失敗します。そのため Analyser の読み出し方式にしています。
- `AnalyserNode` は 128 サンプル単位で更新されます。メインスレッドからは約 384〜896 サンプルずつ進んで見えます（位置合わせで正確に扱っています）。
- `KHR_parallel_shader_compile` は環境によって使えないので、無くても動くようにしてあります。
