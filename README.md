# MOMOSAI VJ — 音に合わせて映像が動く、ライブ用ビジュアル

バンドの演奏や PC で流している音を拾い、**ほぼ遅延なし**でプロジェクターやモニターの映像を変化させるシステムです。

もとは文化祭のバンドステージ用に作りましたが、次の場面でも使えます。

- ダンス発表・DJ
- 弾き語り・合唱・アカペラ・カラオケ
- 司会・スピーチ・朗読（話し声）
- 展示・BGM

**ブラウザだけで動きます。** Chrome / Edge で HTML ファイルを開くだけで、インストールもネット接続も要りません。ブラウザの制約をなくした**単体アプリ版**（Windows / Mac / Linux）も作れます。

## できること

- **音への反応**
  - キック・スネア・ハイハット・キメ（アクセント）・ブレイク明けの一撃を検出し、それぞれ違う動きに割り当てています。
  - **ドラムが無い曲**（ピアノ・ギター・歌）も、発音の立ち上がりに反応します（自動で切り替わります）。
  - **テンポ（BPM）を自動推定**します（倍・半分・付点の取り違えを抑える方式。合成した 20 種類のリズム × 残響・雑音ありで 98% 正解）。タップテンポにも対応し、オートのシーン切替を小節の頭に合わせます。
- **声**
  - **声の高さ（音程）を検出**して色や形に使います（YIN 法。誤差は数セント）。
  - **歌**：音量が下がらずに音程だけ変わるところ（レガート）でも反応します。子音（サ行・タ行など）をドラムとして扱いません。
  - **話し声（司会・MC）を自動で見分けます。** 話し声の間は自動フラッシュ・ブレイク明けの一撃・テンポに合わせた切替を止めます。設定で「MC の間はタイトル」にもできます。
- **音楽のタイプ**: おまかせ / EDM・ダンス / ヒップホップ / アコースティック / しっとり / **歌** / **司会・スピーチ** の 7 種類です。反応の仕方・切替の速さ・使うシーン・フェードの有無が変わります。
- **シーンは 19 種類**です。数字キーが 1 段目、**Shift+数字**が 2 段目です。

| キー | シーン | キー | シーン |
|---|---|---|---|
| 1 | 波紋 | Shift+1 | 声の輪（中央にイベント名） |
| 2 | トンネル | Shift+2 | メロディ線（歌の音程） |
| 3 | 地平線 | Shift+3 | 花火 |
| 4 | オーロラ | Shift+4 | 光の粒 |
| 5 | 万華鏡 | Shift+5 | 波 |
| 6 | グリッチ | Shift+6 | 煙 |
| 7 | イコライザー | Shift+7 | サークル（円形スペクトラム） |
| 8 | 星空 | Shift+8 | 花びら |
| 9 | オシロ | Shift+9 | 声紋（スペクトログラム） |
| 0 | タイトル | | |

  プロジェクター合わせ用のテストパターンもあります（G キー）。
- **シーンの切り替え**：カット・フェード・**ワイプ・円・ブラインド・ズーム・スライド・グリッチ・モザイク・おまかせ**（0.3〜2 秒）。**シーンごとの調整**（速さ・量・大きさ・残像など）を設定パネルのスライダーで変えられます。
- **激しさ**：控えめ / ふつう / **激しい（既定）** / 最大 / **自動**（曲の盛り上がりに合わせて、静かなところは控えめに・サビでは激しく）。激しいほど、キックで画面が寄る・スネアで揺れる・色ずれ・拍ごとに軽く光る・オートの切替が速くなります（しっとり系・歌・司会のタイプでは弱め）。
- **パレットの自動**：曲の区切り（キメ・小節の頭）ごとに、盛り上がりに合った色へゆっくり移します（曲ごとの色の指定があればそのまま）。
- **オーバーレイ**：すべてのシーンの上に、別々に重ねられます。
  - **メディア**（`O`）：**画像**（ファイル・**Ctrl+V で貼り付け**・ファイルを落とす）／**動画ファイル**（MP4・WebM。この PC に保存して次回も）／**画面・タブの取り込み**（YouTube・ニコニコなどを別のタブで再生して取り込む）／**YouTube・ニコニコの URL**（埋め込み。インターネットが必要）
  - **シーン**（`Shift+O`）：もう 1 つのシーンを重ねる
  - **文字**：時計・バンド名・曲名・自由な文字を隅に
  - 単体アプリでは、VJ の映像を透かして**ほかの画面（YouTube など）の上に重ねて表示**もできます。
- **入力**: マイク / ライン入力（USB オーディオ IF）・**PC で再生中の音**（YouTube・DJ ソフトなど。Windows は共有の画面で「画面全体」と「システムの音声を含めて共有する」）・音声ファイル（複数選ぶと連続再生）・デモ音源（バンド・歌・話し声）。
- **使いやすさ**
  - **はじめてのガイド**：パネルの上に 5 つの手順。終わったものに自動で ✓ が付きます。
  - **サウンドチェック**：リハで約 20 秒測ると、音の大きさ・音割れ・会場の雑音を調べて、音楽のタイプと「無音とみなす音量」をおすすめします。
  - **本番前チェック**：音・描画・全画面・出演バンド・光・スリープ・外部連携を緑 / 黄 / 赤で一覧。
  - **出演バンドごとの設定（タイムテーブル）**：名前・セットリスト・ロゴ・音楽のタイプ・色・開演時刻・テロップをバンドごとに覚え、`N` キー・パネル・スマホで切替。演奏中も次のバンドの準備ができます。
  - **シーンを絵で選ぶ**：見本画像つきのボタン（パネル・スマホ）。キーと見本画像の **A4 早見表を印刷** できます。
  - **セットリストを表で編集**：曲の追加・並べ替え、シーンを見本画像から選ぶ、パレット。文字でまとめて貼り付けもできます。
  - **パネルの ①〜⑦ を折りたためます**（見出しを押す。閉じた状態は覚えます。「すべて開く / すべて閉じる」も）。
- **本番向けの機能**
  - セットリスト（曲名表示・曲ごとのシーンと色）
  - オートモード
  - テロップ（Q / W / E）
  - 開演カウントダウン
  - ロゴ画像（タイトル / 隅に透かし）
  - 暗転
  - ロック
  - 前回の続きから再開
- **外部連携**
  - **スマホから操作**（同じ Wi-Fi のスマホのブラウザで。暗証番号つき。**QR コードを読み取るだけでつながる**）
  - **OSC** の受信（照明卓・TouchDesigner などから操作）と送信（音の特徴量）
  - **照明（DMX）**：Art-Net / USB-DMX（Enttec Pro 互換・Open DMX 互換）で、映像の色に合わせて照明を光らせる
  - **MIDI コントローラ**：割り当てを「学習」で自由に変えられる
- **会場に合わせる**
  - 表示の回転（縦置き画面）・左右反転（スクリーン裏からの投影）・サイズと位置の調整
  - **2 画面運用（出力ウィンドウ）**：操作画面を観客に見せずに済みます。手元に出力の映像を小さく表示します。
- **表示の言語**：日本語 / 英語（自動でブラウザの言語に合わせる）。Firefox・Safari でも動きます（一部の機能は Chrome / Edge だけ）。
- **安全**
  - 全画面の強い明滅は 1 秒に 3 回まで（自動テストで全 19 シーン・クロスフェード中・激しさ「最大」でも確認済み）。照明のキックの光も同じ上限
  - **フラッシュの上限**は 2 / 3（推奨・既定）/ 4 / 6 / 10 回・制限なしから選べます。3 回を超える設定にすると、パネルと本番前チェックに警告が出ます（会場への掲示を必ず）
  - 「フラッシュを一切使わない」設定
  - 動きの大きさの調整
- **音から光まで、ソフト側の遅延はおよそ 1 フレーム以内です**（キックの検出は 128 サンプル ≈ 2.7ms 刻み）。

> 企画・設計は **[docs/PLAN.md](docs/PLAN.md)**、課題一覧は **[docs/ISSUES.md](docs/ISSUES.md)** にあります。

## すぐ使う（操作する人向け）

1. `dist/` フォルダをまるごと本番用の PC にコピーします。
   - `C:\momosai-vj\` のように、英数字だけの場所に置くのがおすすめです。
2. 起動用のファイルをダブルクリックします。
   - Windows: `start-windows.bat`
   - Mac: `start-mac.command`（初回は右クリック →「開く」）
   - うまくいかないときは、`momosai-vj.html` を Chrome のウィンドウにドラッグしても開けます。
3. 右側のパネルで入力と「音楽のタイプ」を選び、**▶ 音声入力を開始** を押します。メーターが動けば OK です。
   - パネルの上の **はじめてのガイド** に沿って進めると迷いません。リハでは ① の **サウンドチェック** がおすすめです。
4. ⑥ の **本番前チェック** で確認してから、**ショー開始（全画面）** を押します。
   - プロジェクターを「拡張」でつないだときは、先に **出力ウィンドウを開く（2 画面）** を押します。
5. 本番中のキー操作は次のとおりです。

| キー | 動作 |
|---|---|
| `1`〜`9` | シーン切替（次のビートで。もう一度押すとすぐ） |
| `Shift`+`1`〜`9` | シーンの 2 段目 |
| `0` | タイトル（バンド名） |
| `→` / `←` | 次の曲 / 前の曲（曲名を表示） |
| `N` / `Shift`+`N` | 次のバンド / 前のバンド（演奏中は 2 回押す） |
| `Space` | フラッシュ |
| `B` | 暗転 |
| `A` | オート ON/OFF |
| `Enter` | タップテンポ |
| `Q` `W` `E` | テロップ |
| `G` | テストパターン |
| `O` / `Shift+O` | メディアのオーバーレイ / シーンのオーバーレイ ON/OFF |
| `C` | 色を変える |
| `↑` / `↓` | 感度 |
| `H` | キー一覧 |
| `M` | 設定パネル |
| `L` | ロック（誤操作防止） |

音源なしで試したいときは、入力で **デモ音源** を選びます（バンド演奏・歌・話し声から選べます）。

| アカペラ・カラオケ | マイク / ライン | 歌 | Shift の段のシーン（声の輪・メロディ線） |
| 合唱・吹奏楽・式典 | マイク | しっとり | 「フラッシュを一切使わない」も推奨 |
| 司会・スピーチ・朗読 | マイク / ライン | 司会・スピーチ | 声の輪（Shift+1）の中央にイベント名 |
| 展示・BGM（無人） | 音声ファイル（複数）/ PC の音 | おまかせ | 「起動したら自動的に開始」 |
| 縦長モニター / 裏から投影 | — | — | ④ 表示 で回転・左右反転 |

### スマホ操作・OSC・照明・単体アプリ

- **ブリッジ**（`bridge/`）：スマホ操作・OSC・Art-Net のための小さなサーバーです（依存パッケージなし）。ブラウザ版では `start-bridge-windows.bat` / `start-bridge-mac.command` で起動します（Node.js 18 以上が必要）。パネル ⑦ で「ブリッジにつなぐ」を ON にすると、スマホで開く URL と暗証番号が出ます。「スマホ用の QR コードを表示」を押してスマホのカメラで読み取ると、暗証番号を入れずにつながります（起動した画面と、この PC のブラウザの `http://127.0.0.1:8787/qr` にも QR が出ます）。VJ 本体用の接続口は、同じ PC でファイルから開いた VJ（か localhost のページ）だけを受け付けます。
- **単体アプリ**（`app/`、Electron）：マイクの許可確認なし・出力ウィンドウをプロジェクター側に自動で全画面・PC の音の取り込み（Windows）・ブリッジ内蔵・透過ウィンドウ（映像を透かして、ほかの画面の上に重ねる。⑤ のオーバーレイから）。`cd app && npm install && npm run dist:win`（`dist:mac` / `dist:linux`）で作れます。`npm run smoke` で自己診断（偽のマイクで起動 → 入力・描画・ブリッジ・出力ウィンドウの開閉を確認）します。

## 遅延を小さくするための設計

| 段階 | やっていること |
|---|---|
| 入力 | `getUserMedia` のエコー除去・ノイズ抑制・自動ゲインをすべて OFF にし、WebRTC の音声処理を通しません。`AudioContext({latencyHint:'interactive'})` を使います。 |
| 受け渡し | `AnalyserNode`（平滑化 0）を描画フレームの先頭で同期的に読み出します。前回の末尾 32 サンプルと完全一致する位置を探し、新しく届いた分だけを取り出します。取りこぼしも二重処理もありません。AudioWorklet・SharedArrayBuffer は file:// で使えないうえに、データの新しさは同じなので使いません。 |
| 解析 | FFT は使わず、4 次バターワースの IIR フィルタバンク（5 帯域）を 128 サンプル刻みで回します。低域の 2 帯域は直交エネルギー（y² + (y'/ω)²）で測るので、ベースの波形で値が脈打ちません。 |
| 立ち上がり検出 | 帯域ごとに「dB の上昇量 > 平均 + K·σ + 最小上昇量」で判定します。統計は外れ値を切り詰めて更新し（ウィンソライズ）、帯域の最近のピークと比べて小さすぎる立ち上がりは無視します（相対ゲート）。不応期とヒステリシスで連続発火を防ぎます。 |
| 声 | 12kHz に間引いて YIN（約 36ms の窓）を約 10ms ごとに計算します。音程の変わり目の検出は 50〜90ms 遅れますが、キックの検出とは別系統なので打楽器の反応は遅れません。 |
| 見た目 | 値は「立ち上がりは即時、減衰だけ平滑化」です。ヒットした瞬間のフレームで最大になります。 |
| 描画 | WebGL2 の全画面シェーダです。`desynchronized` と `alpha:false` を使い、描画解像度は自動調整します。シェーダは起動時に事前コンパイルして一度描いておきます。 |

測定値（このリポジトリのテストで確認したもの）は次のとおりです。

| 項目 | 結果 |
|---|---|
| キックの検出遅延（アルゴリズム） | 平均 7.9ms、最大 8.7ms（クリックトラック） |
| 音がグラフに入ってから画面のフレームに反映されるまで（ヘッドレス Chromium・60Hz） | 中央値 9〜16ms（rAF 待ち 0〜16.7ms を含む） |
| 検出精度：ドラムのみ（8 ビート） | キック・スネア・ハイハットの適合率・再現率がいずれも 0.94 以上 |
| 検出精度：ドラム＋ベース＋歪みギター | キックの再現率 0.88、誤検出率 8% |
| 検出精度：ドラムの無い曲（アルペジオ・和音・バラード） | 発音の 85% 以上 |
| テンポ推定（72〜174BPM の 6 曲） | すべて ±2BPM 以内 |
| テンポ推定（68〜200BPM・8 ビート / 4 つ打ち / 2 ビート / ハーフ / シャッフル / ファンク / ヒップホップ / ドラムンベース / まばらなドラム / ドラムなし / テンポが揺れる曲、各 そのまま・残響＋雑音・ライブ相当 の 59 本） | 最後の値が ±3% 以内：58 本（98%）。残る 1 本はドラムンベースを半分（86）と取るもの。10 秒以降に正しい値を出している時間 96%。値のふらつき 12 回（改良前は 45 本・76%・84 回） |
| 音程（70Hz〜1kHz、正弦波・のこぎり波） | 誤差 10 セント以内 |
| 歌のレガート（音程だけ変わる）の検出 | 0.1 秒以内に 94%（歌のタイプ） |
| 話し声の判別（実際の朗読 3 本・読み上げ 3 本・合成音声） | 話し声の 90% の時間を判定（話し始めから 2〜3.5 秒）。器楽 6 曲・歌入り 1 曲・合成の歌や合唱を話し声と判定した時間は 0% |

実機での総合遅延（AD 変換・OS・プロジェクタを含む）は、手順書の「遅延の測り方」の方法で確認してください。プロジェクタの「ゲームモード」が一番効きます。

## 開発

```bash
npm install             # playwright（テスト用。ブラウザのダウンロードは不要な環境を想定）
npm run build           # dist/momosai-vj.html（単一ファイル）を生成
npm test                # build → テスト用音声生成 → 単体テスト → E2E
npm run test:unit       # DSP・演出・ブリッジ・辞書の単体テスト（Node だけで動く）
npm run test:e2e        # Playwright（Chromium・偽マイク）で dist を file:// で開いて検証
node tools/check-scenes.mjs [シーンID ...]   # シーンの見た目（PNG）・明るさ・光過敏のチェック
npm run thumbs          # シーンの見本画像（src/ui/thumbs.js）を作り直す（シーンを追加・変更したとき）
cd app && npm install && npm run smoke       # 単体アプリの自己診断（Electron をダウンロードします）
```

- **開発中の表示確認:** `index.html` をそのまま Chrome で開けばそのまま動きます（ビルド不要）。
- **テスト用の URL パラメータ:**
  - `?test=1`: テスト API `VJ.testing` を有効にする
  - `&scale=1`: 描画倍率を固定する
  - `&forceShaderFail=glitch`: シェーダの失敗を再現する
- **ソースの形式:** classic script（ES Modules 不使用）です。file:// で動かすためと、Node のテストから `vm` で読み込むためです。
- **表示の文言:** 日本語を原文にして `VJ.t('…')` で訳します。英語は `src/core/i18n-en.js`。辞書の漏れは単体テストと E2E（英語表示に日本語が残っていないか）で確かめています。

### ファイル構成

```

src/scenes/             シーン（GLSL）と仕上げパス
```

### シーンの追加

`src/scenes/xxx.js` で `VJ.scenes.register({ id, key, name, nameJa, params, frag, update })` を呼び、`index.html` に script タグを足します。

- 共通の uniform（`u_kick`, `u_kickEv[8]`, `u_level`, `u_pal[4]`, 声の `u_pitch` `u_voiced` `pitchHist()`, 調整値 `u_param` など）は `src/scenes/common.js` を参照してください。
- `key` は `'1'`〜`'9'`（1 段目）か `'s1'`〜`'s9'`（Shift の段）です。
- `params`（最大 4 つ）を書くと、設定パネルの「シーンごとの調整」にスライダーが出ます（シェーダでは `u_param.x` …、`update` では `fx.param[0]` …）。
- **ビートに合わせて画面全体の明るさを大きく変えないでください。** 動き・大きさ・色相で反応させます。
- `node tools/check-scenes.mjs xxx` と光過敏テスト（`test/e2e/render.test.mjs`）が通ることを確認してください。
- `npm run thumbs` で見本画像を作り直します（単体テストが、見本画像の無いシーンを見つけます）。

## 確認済みの技術事項

ヘッドレス Chromium 141 と Electron 44 で確認しました。

- file:// でも安全なコンテキストとして扱われ、`getUserMedia`・`localStorage`・URL のクエリが使えます。
- file:// では `AudioWorklet.addModule` が Blob URL でも失敗します。そのため Analyser の読み出し方式にしています。
- `AnalyserNode` は 128 サンプル単位で更新されます。メインスレッドからは約 384〜896 サンプルずつ進んで見えます（位置合わせで正確に扱っています）。
- `KHR_parallel_shader_compile` は環境によって使えないので、無くても動くようにしてあります。
